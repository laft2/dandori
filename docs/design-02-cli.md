# 技術設計 第2部：CLI `dan` の仕様

## 1. 方針
- 実装には `clap`（derive）を使う。ロジックはすべて core に任せ、CLIは引数の解析と出力の整形だけを行う
- **人が読みやすいこと**と**AIが扱いやすいこと**を両立させる
  - デフォルトの出力は人が読むためのテキスト
  - `--json` を付けると、安定したスキーマのJSONを出力する
- 操作者は常に `cli` として記録する

## 2. 共通オプション
| オプション | 環境変数 | 説明 |
|---|---|---|
| `--json` | | JSONで出力する（エラーもJSONで標準エラー出力に出す） |
| `--session <id>` | `DANDORI_SESSION` | 操作を記録するセッションを指定する（3章） |
| `--db <path>` | `DANDORI_DB` | DBファイルの場所を指定する（開発・テスト用） |
| `-q, --quiet` | | 成功したときは何も出力しない |

## 3. タスクと位置の指定方法
| 書き方 | 意味 | 例 |
|---|---|---|
| `12` または `#12` | タスクID | `dan done 12` |
| `@1`、`@2`… | キューの中の現在の位置（1始まり） | `dan done @1`（先頭のタスクを完了） |

- IDは変わらないので、AIには**ID指定を推奨**する（位置は他の操作で変わってしまう）
- 挿入する位置は、どのコマンドでも共通で `--top` / `--bottom` / `--at <n>` / `--before <ref>` / `--after <ref>` で指定する
  - `--at 3`：キューの3番目に入れる（それまでの3番目以降は1つずつ後ろにずれる）

## 4. コマンド一覧

### 4.1 参照
| コマンド | 説明 |
|---|---|
| `dan` / `dan now` | 「今やること」（先頭のタスク）を詳細表示する |
| `dan list` | キューを一覧表示する |
| `dan list --hold` | 保留中のタスクを一覧表示する |
| `dan list --done [--month YYYY-MM]` | 完了したタスクを一覧表示する（`--month` を省略すると当月） |
| `dan list --deleted` | 削除したタスクを一覧表示する |
| `dan show <ref>` | タスクの詳細（メモを含む）を表示する |
| `dan search <query> [--all]` | タイトルとメモを検索する（`--all` を付けると完了・保留も対象） |

### 4.2 変更
| コマンド | 説明 |
|---|---|
| `dan add <title> [opts]` | タスクを追加する。**デフォルトでは末尾に入れる**。位置オプションで任意の位置に挿入できる |
| `dan edit <ref> [opts]` | タスクを編集する |
| `dan move <ref> <位置>` | 並べ替える（`--top` / `--bottom` / `--at` / `--before` / `--after`） |
| `dan done [<ref>...]` | 完了にする。引数を省略すると先頭のタスクを完了にする |
| `dan reopen <ref>` | 完了を取り消す（元の位置に戻る） |
| `dan hold <ref>` | 保留にする |
| `dan resume <ref> [--top\|--bottom]` | 保留を解除する（デフォルトは先頭） |
| `dan delete <ref>...` | 削除する（論理削除。ロールバックで戻せる） |
| `dan restore <ref>` | 削除したタスクを、キューの元の位置に戻す |

**`add` / `edit` のオプション**
| オプション | 説明 |
|---|---|
| `--title <text>` | タイトル（`edit` で使う） |
| `--memo <text>` | メモを設定する |
| `--memo-file <path>` | メモをファイルから読み込む。`-` を指定すると標準入力から読み込む（複数行のMarkdown向け） |
| `--append-memo <text>` | メモの末尾に追記する（`edit` で使う） |
| `--due <date>` | 期限。`2026-11-30` / `today` / `tomorrow` / `+3d` / `fri` などを受け付ける |
| `--no-due` | 期限を消す（`edit` で使う） |
| `--url <url>` | URLを追加する（複数回指定できる） |
| `--remove-url <url>` / `--clear-urls` | URLを削除する（`edit` で使う） |
| `--top` / `--bottom` / `--at` / `--before` / `--after` | 挿入する位置（`add` で使う。省略すると末尾） |
| `--hold` | 保留として追加する（`add` で使う） |

### 4.3 セッション・ロールバック
| コマンド | 説明 |
|---|---|
| `dan session start [--label <text>]` | アクティブセッションを開始し、セッションIDを出力する |
| `dan session end` | アクティブセッションを終了する |
| `dan session list [--limit n]` | 最近のセッションを、操作の件数とともに一覧表示する |
| `dan undo` | 現在のセッションの直前の操作を1つ取り消す |
| `dan redo` | 現在のセッションで取り消した操作をやり直す |
| `dan rollback [--session <id>] [--skip-conflicts] [--dry-run]` | セッションの操作をまとめて取り消す。`--session` を省略すると、現在のセッションまたは直前のセッションが対象 |
| `dan history [--limit n] [--session <id>]` | 操作履歴を表示する |

- `undo` / `redo` は**セッションの中だけ**で動く。人間のアプリ上の操作には影響しない（[design-01-db.md](design-01-db.md) 5.2）
- 競合があった場合、`rollback` は何も変更せず、終了コード4で競合しているタスクを報告する。`--skip-conflicts` を付けると、競合していないものだけを戻す

### 4.4 その他
| コマンド | 説明 |
|---|---|
| `dan report [--month <月>] [--include-recurring] [--format md\|json]` | 月次の振り返り用に完了タスクを出力する（Markdown） |

**`--month` に指定できる値**
| 値 | 意味 |
|---|---|
| 省略 / `last` | 前月（デフォルト） |
| `this` | 今月（月末に振り返る場合） |
| `YYYY-MM` | 指定した月 |
| `dan guide` | AI向けの使い方ガイド（Markdown）を出力する（7章） |
| `dan backup` | 手動でバックアップする |
| `dan info` | DBの場所、バージョン、件数を表示する |

## 5. 出力例

**`dan list`**
```
  ▶ #12  見積書を作成して送付            期限 11/20  🔗1
    #15  PRレビュー                                  🔗2
    #9   経費精算                         期限 11/30(超過)
  保留 1件（dan list --hold で表示）
```

**`dan report --month 2026-10`**
```markdown
# 2026-10 完了タスク（12件 / 定期タスク 1件を除外）

## 2026-10-03
- 見積書を作成して送付 (#12)
  - URL: https://example.com/board/123
  - メモ: 先方の要望で2案出し
...
```

**`--json` の例（`dan show 12 --json`）**
```json
{
  "id": 12,
  "title": "見積書を作成して送付",
  "memo": "先方の要望で2案出し",
  "due_date": "2026-11-20",
  "urls": ["https://example.com/board/123"],
  "status": "queued",
  "source": "manual",
  "queue_position": 1,
  "created_at": "2026-11-18T00:20:00+09:00",
  "updated_at": "2026-11-18T00:20:00+09:00",
  "completed_at": null
}
```
- 変更系のコマンドは `{"ok": true, "operation_id": 431, "task": {...}}` を返す
- エラーは `{"ok": false, "error": {"code": "not_found", "message": "..."}}` を返す
- JSONの日時はローカルのオフセット付きで出力する（DBの内部ではUTC）

## 6. 終了コード
| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | その他のエラー |
| 2 | 引数の誤り |
| 3 | 対象が見つからない |
| 4 | 競合（ロールバックや取り消しができない） |
| 5 | DBにアクセスできない（ロック待ちのタイムアウトなど） |

## 7. AI向けガイド（`dan guide` の出力の骨子）
`CLAUDE.md` に `dan guide` の出力を貼るか、「作業の前に `dan guide` を読むこと」と書いておく運用を想定する。
```markdown
# Dandori (dan) の使い方
- 作業を始めるときは `dan session start --label "<作業内容>"` を、終わったら `dan session end` を実行する
- 一覧の確認は `dan list --json`、詳細の確認は `dan show <id> --json`
- タスクはIDで指定する（`@n` の位置指定は、直前に一覧を確認したときだけ使う）
- 複数行のメモは `--memo-file -` で標準入力から渡す
- 間違えたら `dan undo`。セッション全体を戻すときは `dan rollback`
- 完了・削除などの操作に人間の確認は不要（あとからロールバックで戻せるため）
```

## 8. 決定事項
- **C1** `dan add` のデフォルトは末尾。`--at` などで任意の位置に挿入できる
- **C2** `dan report` のデフォルトは前月。`--month this` で今月も指定できる
- **C3** 完了・削除に確認は求めない（ロールバックで戻せるため）
